### U1-F1: Importing the shipped `theme.css` preset silently remaps Tailwind's container widths (`max-w-md`, `w-lg`, `min-w-sm`, …) to 10–28px spacing values
- severity: S1
- category: build-packaging
- rules: []
- scope: consumer-visible
- confidence: plausible
- verified_by: "Compiled a probe (`max-w-md max-w-sm max-w-xl w-md min-w-lg max-w-2xl`) with the audit-build Tailwind 4.3.3 CLI, once importing src/styles/theme.css and once without (docs/audit/_work/scratch/U1/consumer-in.css, default-in.css → consumer-out.css, default-out.css). With the preset: `.max-w-md { max-width: var(--ui-spacing-md) }` (16px), `.max-w-sm` → `--ui-spacing-sm` (10px), `.max-w-xl` → `--ui-spacing-xl` (28px), `.w-md` → `--ui-spacing-md`, `.min-w-lg` → `--ui-spacing-lg`; without it they resolve to `--container-md` etc. Tailwind lib.js contains `\"max-w\",[\"--max-width\",\"--spacing\",\"--container\"]` — spacing is consulted before container."
- locations:
  - src/styles/theme.css:111-119
  - scripts/sync-theme.mjs:199-201
  - skills/dooph-design-system-theming/references/token-contract.md:218-228
- evidence: |
    theme.css:113  --spacing-xs: var(--ui-spacing-xs);
    theme.css:114  --spacing-sm: var(--ui-spacing-sm);
    theme.css:116  --spacing-md: var(--ui-spacing-md);
    theme.css:117  --spacing-lg: var(--ui-spacing-lg);
    theme.css:118  --spacing-xl: var(--ui-spacing-xl);
    token-contract.md:228  This makes every dooph utility generate in the app build and overrides colliding defaults; ...
    probe output (with preset):  .max-w-md { max-width: var(--ui-spacing-md); }   (default: var(--container-md) = 28rem)
- impact: A consumer who follows the documented setup (importing `theme.css` into their own Tailwind build) has every existing `max-w-{xs,sm,md,lg,xl}`, `w-{…}` and `min-w-{…}` container class in their app collapse from 20–36rem to 8–28px, with no build error. The docs frame "overrides colliding defaults" as a feature (examples given: `font-sans`, numeric spacing), so nothing warns that 5 of the DS spacing keys (`xs sm md lg xl`) shadow Tailwind's container scale. The DS's own components do not use those classes (rg over src/**/*.tsx finds none), so the package's own build never exposes the problem.
- recommendation: Decide whether the named spacing keys belong in the consumer preset under the `--spacing-*` namespace at all (they collide by construction with the `--container-*` lookups); at minimum document the collision and the affected utilities in token-contract.md's "Tailwind Consumer Preset" section.
- breaking: major
- contract: n/a
