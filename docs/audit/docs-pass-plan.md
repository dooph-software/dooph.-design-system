# Docs Pass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild every skill and doc in the repo from the code at HEAD so that they are correct, focused and tested. Make every rule that can be measured a lint failure. Delete every doc that could mislead an agent.

**Architecture:**
- Facts come from code, never from old docs. A mechanical public-surface diff against v5.3.0 drives the CHANGELOG.
- Inventories (components, tokens) are GENERATED by a script, and lint fails if they go stale.
- Measurable rules live in `scripts/check-conventions.mjs`, which runs inside `npm run lint`. Skills carry only the judgement rules, and each skill names the check that enforces its measurable neighbours.
- Every doc passes an independent claim check: fresh agents verify each atomic claim against file:line. Every skill passes behaviour tests: the same task is run without and with the skill.

**Tech Stack:**
- Repo: React 19, Radix UI, Tailwind v4, cva, tsup, Storybook 10 (port 6007, launch name `storybook`).
- Scripts: Node 24 ESM scripts, plus the TypeScript compiler API (already a devDependency) for the props inventory.

## Global Constraints

- Never commit, stage or push. Never bump `package.json` `version`. The maintainer commits and cuts v6.

- CHANGELOG history: keep 1.0.0/1.1.0 as they are. Add one line saying the 2.0–5.3 notes live in git history (tags `v2.0.0` … `v5.3.0`). Write a full `[Unreleased]`.
- Delete, don't archive: the root planning files (`executor-prompt-oss-publication.md`, `2026-09-20-visx-charts-design.md`, `2026-09-20-visx-charts-figma-checklist.md`), `docs/superpowers/`, `.claude/research/`, the old DS skills, and finally `docs/audit/`. Delete `docs/audit/` only after the maintainer confirms at the end.
- Measurable rules go in `npm run lint`, through `scripts/check-conventions.mjs`.
- Write in plain words. Never use a bare ID (F-019, WI-061, D-07) in any doc. No history in present-tense docs; history goes in git and the CHANGELOG only.
- Every rule is paired with the failure it prevents. One skill per job. Skill descriptions start with "Use when…", give triggering conditions only, never summarise the workflow, and stay under 500 characters.
- Re-derive every fact from code at HEAD. Never port text from an old skill or doc. FINDINGS.md §4 lists 158 old false claims, so check against it that none of them reappear.
- Repo-wide renames happen by a deterministic script. Never kill processes by name. Run at most 5 agents at once, and each writes its output to disk as it goes.
- Figma: not needed. If a task finds it does need Figma and the MCP is expired, STOP and tell the maintainer.
- Leave the third-party skills untouched: `skill-creator`, `using-airbnb-visx-lib`, and `skills-lock.json` entries other than the radix one, which is already gone.
- `file-header-contracts` (the repo copy of the maintainer's personal skill) is deleted, per doc-refresh.md. AGENTS.md keeps the always-on contract rules.

### Task 2: Permanent convention checks in `npm run lint`

**Files:**
- Create: `scripts/check-conventions.mjs`
- Modify: `package.json` (`"lint": "tsc --noEmit && node scripts/check-conventions.mjs"`)
- Source material: `docs/audit/_work/scratch/{scoreboard,expression-check,dark-inventory,rule-gaps,text-leaves}.mjs`

**Interfaces:**
- Produces: a script that exits 1 and prints `FAIL <rule name>: <file:line> <match>` for each violation, and otherwise prints `conventions: N checks passed`. Each check has a plain-English name and a one-line "why" that the skills quote. The check names are a contract, because Tasks 5 and 6 cite them verbatim.
- Checks (all target 0):
  - motion timing literals outside tokens.css;
  - arbitrary px/rem in classNames;
  - numeric Tailwind spacing (zero resets allowed);
  - raw `var(--ui-*)` in className brackets;
  - hand-rolled focus rings;
  - hand-rolled disabled looks;
  - value callbacks not named `onValueChange`;
  - default exports in component modules;
  - text-style classes outside Text components;
  - typography utilities or inline font styles;
  - hex colour literals in components;
  - Tailwind default radii and shadows;
  - `ElementRef`;
  - forwardRef without `displayName`;
  - Tailwind variant on a DS package class;
  - `var()` in SVG geometry attributes;
  - runtime theme detection;
  - hardcoded font families;
  - the expression system (expression-check's four rules);
  - dark aliases missing from `.dark`, and redundant non-alias `.dark` lines;
  - `"use client"` only in the files of an explicit allowlist (the current 27, each with a one-line reason; a new file must be added with its reason);
  - JS timers and animation loops only in an explicit allowlist (the current 5, each with its reason);
  - the generated theme is fresh (`sync-theme.mjs` output equals the files on disk);
  - the generated doc references are fresh (Task 3);
  - the skill mirrors match (Task 9).

- [ ] **Step 1: Failing test first.** Create `docs/audit/_work/docs-pass/check-fixtures/` with one tiny `.tsx`/`.css` file per check, each holding exactly one violation, and add a `--fixtures <dir>` flag that runs the code checks over that dir instead of `src/`. Run it. Every check must report exactly its own fixture, and a check that reports nothing is broken.
- [ ] **Step 2:** Implement by porting the scratch scripts, using the same regexes already validated in the audit. Strip comments before matching code checks, so a header contract can name a forbidden class.
- [ ] **Step 3:** `node scripts/check-conventions.mjs --fixtures …` lists all fixtures, one per check. `node scripts/check-conventions.mjs` on `src/` passes, because every metric is 0 today.
- [ ] **Step 4:** `npm run lint` exits 0. Temporarily add `<span className="text-style-body">x</span>` to a component; lint exits 1 naming that file:line. Revert.
